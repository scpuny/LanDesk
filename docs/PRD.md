# LanDesk PRD（产品需求文档）

> 产品归属：Lan Studio 内网工具生态，内置远程桌面模块
> 文档版本：V0.1 MVP版
> 状态：草稿
> 技术栈：Rust + Tauri + 裁剪libav(H.264) + Quinn(QUIC) + ICE/STUN + mDNS
> 核心定位：**内网优先无中心自动发现，外网轻信令P2P、可中继兜底，稳定优先、低资源占用、自托管、无第三方依赖的远程桌面工具**

## 1. 概述

### 1.1 背景

现有远程桌面工具痛点：

1. RustDesk：依赖公共中继、隐私不可控，自建部署繁琐；
2. FRP/RDP：配置复杂，NAT穿透麻烦；
3. 商业工具：有联网校验、限流、收费；
4. 现有 Lan Studio 已经实现 mDNS 局域网设备发现，希望复用这套能力，做配套远程桌面；
5. 需求重点：**稳定优先，不希望裸写多平台原生硬编码踩驱动坑，使用裁剪libav做统一编码层，硬件编码优先、OpenH264软编兜底**。

LanDesk 不是独立大客户端，是 Lan Studio 的内置子模块，也支持独立单文件二进制运行。

### 1.2 产品目标（MVP）

1. 局域网：mDNS 自动发现、零配置直连，无中心服务器；
2. 外网：可选自建轻量信令服务，ICE打洞P2P优先，打洞失败支持中继兜底；
3. 编码链路稳定降级：硬编码（NVENC/QSV/V4L2-M2M/VideoToolbox）→ OpenH264软编；
4. 支持 Windows / Linux / macOS / OK3568 嵌入式；
5. 端到端加密，不依赖第三方服务器传输画面；
6. 低资源开销，优先脏矩形更新，不整帧全量编码；
7. 最小化依赖：静态链接裁剪ffmpeg，用户无需单独安装ffmpeg。

### 1.3 范围界定（In Scope / Out of Scope）

✅ 包含（MVP）

- 屏幕采集、脏矩形差异检测
- libav H.264 编码分层降级
- QUIC 双通道：视频流（不可靠）+ 控制通道（可靠）
- mDNS 局域网设备发现
- ICE/STUN P2P打洞
- 键鼠注入、双向剪贴板（文本）
- 会话鉴权、密钥协商、AES-GCM加密
- 轻量信令服务（可选组件）、中继转发（可选）
- 断线自动重连、编码器异常重置恢复
- 多显示器切换

❌ 暂不包含（MVP不做，后续版本）

- 文件传输
- 语音传输
- 多账号权限系统、组织管理
- AV1 / H.265（后续迭代）
- 移动端控制端
- 录像、回放
- 网页版控制端

## 2. 用户角色 & 场景

### 角色

1. 开发者/运维（主用户）：家里多台主机、PVE、OK3568开发板、办公机器；
2. 内网运维：局域网批量调试设备，不想配置IP；
3. 外出访问：在外网远程连家里开发主机，接受部分网络环境P2P打不通，需要中继兜底。

### 核心场景

1. **内网场景**：同局域网，打开 Lan Studio，自动列出所有在线 LanDesk 主机，一键连接，无配置；
2. **外网场景**：受控端上线后上报设备ID到自建轻信令，控制端输入ID + 密码，ICE尝试P2P直连；打洞失败自动切中继；
3. **异常场景**：显卡休眠、编码器句柄失效、显示器插拔、分辨率变更 → 编码器自动关闭重建，会话尽量不断；
4. **弱网场景**：网络拥塞时，动态下调码率、增大I帧间隔，防止UDP队列爆掉。

## 3. 整体架构设计（混合架构）

> 【内网：无中心化 mDNS 直连】
> 【外网：轻信令中心化（只交换ICE候选、密钥、设备ID），流量优先P2P；失败走中继】
> 信令带宽极低，只传信令，**视频画面流量不经过信令服务**。

四层链路：

1. **发现层**：mDNS（局域网） + 信令注册（外网）
2. **采集层**：平台原生屏幕采集API + 脏矩形检测
3. **编码层**：封装 libav 统一编码器，自动降级策略
4. **传输层**：QUIC
   - Stream A：可靠流：鉴权、键鼠事件、剪贴板、控制指令
   - Stream B：不可靠Datagram：H264 NALU视频流，自定义丢包策略
5. **输入层**：系统API键鼠注入
6. **加密层**：会话密钥ECDH协商，所有业务流 AES-GCM

> 编码降级顺序（严格）
>
> | 平台 | 降级链 |
> |---|---|
> | Windows | h264_qsv → h264_nvenc → h264_amf → OpenH264 |
> | Linux PC | h264_qsv → h264_nvenc → h264_v4l2m2m → OpenH264 |
> | OK3568 | h264_v4l2m2m → OpenH264 |
> | macOS | h264_videotoolbox → OpenH264 |

## 4. 功能需求（FR）

> 优先级：P0=必须，P1=重要，P2=后续迭代

### FR-01 设备发现 P0

- FR-01.1 受控端启动后，局域网内通过 mDNS 广播自身信息：设备名、设备ID、分辨率、支持编码列表；
- FR-01.2 控制端 mDNS 监听，自动展示局域网在线设备列表；
- FR-01.3 外网模式：受控端可选配置信令地址，主动注册设备ID；
- FR-01.4 设备离线自动从列表移除。

### FR-02 连接与鉴权 P0

- FR-02.1 连接方式：局域网点击设备 / 外网输入设备ID；
- FR-02.2 预共享密码校验；支持临时一次性密码；
- FR-02.3 ECDH 协商会话密钥，后续所有流量 AES-GCM；
- FR-02.4 连接失败给出明确原因：密码错误、无路由、打洞失败、中继不可用。

### FR-03 屏幕采集与脏矩形 P0

- FR-03.1 Windows：Graphics Capture；Linux：PipeWire；macOS：CGDisplayStream；
- FR-03.2 开启脏矩形对比，只发送画面变化区域给编码器；
- FR-03.3 支持多显示器切换，可选择指定显示器；
- FR-03.4 分辨率变更、显示器热插拔事件捕获，触发编码器重建。

### FR-04 编码模块（核心稳定模块） P0

- FR-04.1 封装 libav 统一编码器 Trait，对外接口统一：open、send_frame、recv_nalu、close；
- FR-04.2 编码器按优先级尝试硬件编码器，初始化失败自动降级 OpenH264；
- FR-04.3 不使用 avformat 容器，只输出裸H264 NALU；
- FR-04.4 swscale 统一色彩空间转换（RGB→NV12）；
- FR-04.5 支持运行时接收网络反馈，动态调整码率、I帧间隔；
- FR-04.6 编码器异常、花屏、句柄失效：自动 close + 重新 open，不直接断开会话。

### FR-05 网络传输 P0

- FR-05.1 Quinn QUIC 双通路：可靠控制流 + 不可靠视频Datagram；
- FR-05.2 ICE+STUN NAT打洞；
- FR-05.3 P2P连通性探测，成功走直连；失败自动切换中继；
- FR-05.4 断线自动重试，最多N次重试，重试间隔指数退避；
- FR-05.5 视频包做简单序号，接收端做抖动缓冲，乱序丢弃过期帧。

### FR-06 远程输入 P0

- FR-06.1 鼠标移动、左键/右键/滚轮、键盘按键双向回传；
- FR-06.2 键盘支持修饰键 Ctrl/Shift/Alt；
- FR-06.3 控制端鼠标坐标映射到受控端分辨率。

### FR-07 剪贴板同步 P1

- FR-07.1 文本剪贴板双向同步；
- FR-07.2 大小上限保护，防止超大文本冲击通道。

### FR-08 受控端配置面板 P1

- FR-08.1 设置访问密码、设备名称；
- FR-08.2 开关：mDNS广播、外网信令注册、中继开关；
- FR-08.3 手动指定STUN地址、信令地址；
- FR-08.4 日志级别设置、查看编码器日志（方便排错）；
- FR-08.5 编码参数预设：流畅（低码率）、平衡、高清。

### FR-09 控制端预览窗口 P1

- FR-09.1 自适应缩放、原始尺寸；
- FR-09.2 全屏模式；
- FR-09.3 实时状态栏：延迟、编码类型、连接方式（内网/P2P/中继）、丢包率。

### FR-10 可选组件：轻信令服务 P1

- FR-10.1 轻量Rust服务，只交换ICE候选、设备ID；
- FR-10.2 无画面流量转发；无数据库，内存存储在线设备；
- FR-10.3 支持独立二进制部署，单文件。

### FR-11 可选组件：中继服务 P1

- FR-11.1 P2P失败时中转QUIC流量；
- FR-11.2 可独立开关，用户可以选择不自建中继（打不通就拒绝连接）。

## 5. 非功能需求 NFR（稳定优先）

**NFR-01 稳定性**

- 显卡休眠、显示器插拔、分辨率切换，编码器自动重置，会话尽量保活；
- 硬件编码器驱动异常时稳定降级 OpenH264，不崩溃；
- 连续稳定运行72h无内存泄漏、无句柄泄露。

**NFR-02 性能指标（参考）**

- 内网场景：端到端延迟 < 30ms；
- P2P外网良好网络：延迟 < 80ms；
- 硬编码模式，受控端CPU占用常态 < 8%（不含采集）；
- 脏矩形生效时，静止桌面几乎不产生编码数据包。

**NFR-03 安全**

- 禁止裸流传输；所有通道强制AES-GCM；
- 密码不以明文存储；
- 受控端默认不主动暴露公网，需要手动开启外网信令注册；
- 无内置第三方STUN/信令，全部由用户自己配置。

**NFR-04 兼容性**

- Windows10 / Windows11；Linux（Debian/Ubuntu）；macOS；OK3568；
- 老机器无硬编自动切 OpenH264，保证可用性。

**NFR-05 包体积**

- ffmpeg 裁剪编译，只保留 avcodec / avutil / swscale + 需要的编码器；
- 静态链接，单二进制，无外部依赖库。

**NFR-06 可观测性**

- 分级日志：debug/info/warn/error；
- 日志输出：连接方式、编码器类型、码率、丢包、重置事件；
- 方便定位硬编驱动、NAT打洞类问题。

## 6. 数据协议简要设计（自定义轻量协议，不兼容RDP/VNC）

三层报文：

1. **控制报文**（QUIC可靠流）：鉴权、键鼠、剪贴板、编码器参数通知、重连指令；
2. **视频报文**（QUIC Datagram）：NALU分片、帧序号、时间戳；
3. **ICE候选报文**（信令通道）：candidate、SDP简化字段。

> 不引入复杂SDP完整实现，简化ICE字段，降低复杂度。

## 7. 风险列表

| 风险 | 影响 | 预案 |
|---|---|---|
| 不同厂商硬编驱动行为不一致 | 部分机器硬编反复失败 | 强制降级OpenH264兜底，日志上报编码器失败原因 |
| 对称NAT环境下ICE打洞成功率低 | 外网经常连不上 | 提供中继兜底；同时提示用户配置IPv6 |
| 脏矩形检测CPU开销高 | 老机器采集占用高 | 可开关脏矩形，降级成全帧模式 |
| libav裁剪编译交叉编译麻烦（OK3568 ARM） | 嵌入式版本构建困难 | 提供预制编译脚本，区分x86_64/aarch64 |
| QUIC在部分严格防火墙被拦截 | 外网无法建立连接 | 后续预留TCP备选通道（MVP暂不做） |

## 8. 里程碑（MVP开发顺序）

- **M1**：采集 + 脏矩形模块（先跑通画面采集，不编码传输）
- **M2**：libav 编码器封装，降级逻辑验证，单独单元测试编码器
- **M3**：QUIC 双通道、NALU收发、解码渲染（本地回环测试）
- **M4**：mDNS局域网发现 + 内网完整链路打通
- **M5**：键鼠输入、剪贴板、鉴权加密
- **M6**：ICE/STUN P2P打洞、轻信令服务开发
- **M7**：中继服务、异常恢复、编码器自动重置
- **M8**：Tauri UI面板、配置页、状态展示、整体联调测试
- **M9**：全平台打包、OK3568交叉编译、稳定性压测

## 9. 验收标准（MVP上线标准）

1. 内网：同局域网设备 mDNS 发现，一键连接，画面流畅，键鼠正常；
2. 硬编机器优先硬编，硬编手动破坏（驱动禁用）自动切OpenH264；
3. 分辨率切换、显示器插拔，编码器自动重建，会话不崩溃；
4. 外网：配置自建信令，P2P连通正常；打洞失败自动切中继；
5. 断线后自动重连；日志清晰可查；
6. Windows/Linux/macOS/OK3568 四个平台均可编译运行。
